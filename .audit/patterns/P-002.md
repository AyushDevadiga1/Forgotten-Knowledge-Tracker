# P-002 — Migrations never invoked by any runtime entry point

- PATTERN_ID: P-002
- ROOT_CAUSE_PATTERN:
  `run_migrations()` / `ensure_base_schema()` are not called by any runtime startup
  path; every entry point calls `init_all_databases()` (models `create_all` only).
  Schema evolution therefore requires an out-of-band manual/CI step that production
  deployments can skip, leaving provisioned DBs behind the migration DDL.
- ORIGIN_FINDING: FKT-F-002
- SEARCH_METHOD:
  - grep `run_migrations|init_all_databases|create_all|ensure_base_schema|init_db`
    (38 hits); read every entry point and provisioning helper.
  - Verified CI: .github/workflows/ci.yml:39-42 runs
    `python -m tracker_app.db.migrations` as an explicit step — confirming
    migration is a manual/CI-only operation, not wired into startup.
- CANDIDATES: none.
- CONFIRMED_SIBLINGS:
  - None — the defect is a single missing invocation shared by all entry points,
    not a repeated instance. All startup paths verified:
    web/app.py:28-29, tracking/loop.py:274, main.py:6-7, setup.py:144-149,
    db/db_module.py:15-23 (create_all only).
- REJECTED_SIBLINGS:
  - tools/launcher.py:46-51 (`launch_migrate` subcommand) — deliberate manual
    escape hatch, not a sibling.
  - learning/learning_tracker.py:308-309 and learning/concept_scheduler.py:302-303
    (`init_all_databases` inside `__main__` guards) — same gap, not separate
    instances; subsumed by the finding.
- OPEN_QUESTIONS: none.
