# P-004 — datetime serialization format divergence ('T' vs space) in raw SQL writers

- PATTERN_ID: P-004
- ROOT_CAUSE_PATTERN:
  Raw-SQL writers serialize datetimes with `datetime.isoformat()` (T separator)
  into TEXT columns, while every reader uses SQLAlchemy DateTime which binds and
  parses the space format ("%Y-%m-%d %H:%M:%S.%f"). SQL string comparisons and
  ORDER BY then interleave the two formats with inconsistent ordering, and
  fromisoformat-based lookups miss T-format rows.
- ORIGIN_FINDING: FKT-F-004
- SEARCH_METHOD:
  - grep `isoformat|strftime|str(datetime)` (36 hits); traced every hit to a
    writer, reader, or serializer.
  - Cross-checked regression doc in tests/test_api.py:324-328.
  - sqlite3 raw-access sweep (23 hits): all non-writer uses are read-only SELECTs.
- CANDIDATES:
  - scripts/debug/patch_sessions.py:23-26 — writes `new_end.isoformat(sep=' ')`
    (CORRECT space format). It is a repair tool written to fix this bug class,
    not a sibling; kept as candidate-observation.

    tools/preflight_check.py:52) remain the only T-format DB writers.
